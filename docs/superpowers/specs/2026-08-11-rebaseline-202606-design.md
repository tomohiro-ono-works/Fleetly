# 202606再始動設計

## 目的

202607改修後の状態を現行原本として修復するのではなく、最後に正常動作していた202606を動作基準として再始動する。202607はGitHub上に保全し、設計上有用なバックエンド要素だけを選択的に移植する。

## 基準の扱い

- 動作原本: 202606の最後に正常動作していたコミット
- 保全対象: 現在の202607改修状態。削除・上書きせず、参照用に残す
- UI正本: 202606の見た目、レイアウト、操作感、画面遷移
- バックエンド設計参照: 202607の責務分離、security、runtime、resource、logの設計
- 新規JSライブラリ: 202606のUI契約に適合するものだけ再利用

## 進め方

1. 現在の作業ツリーと202607改修状態を保全する。
2. 202606の正常コミットと再現手順を確定する。
3. 202606ベースの再始動ブランチで、起動・保存・読込・実行を確認する。
4. 202606 UIの画面・操作・遷移を正本として記録する。
5. 直近のJSライブラリを適合性別に分類し、画面単位で段階的に接続する。
6. 202607の設計を、既存動作を壊さない小単位でバックエンドへ移植する。
7. 各移植単位でPython、UI、E2Eの回帰確認を行う。

## やらないこと

- 202607の現行UIを正本として修復しない。
- 202607の実装を一括で202606へマージしない。
- 202606の画面体験を、未確認の新UIライブラリ都合で変更しない。
- 現在の作業ツリーに含まれる不明な変更を、根拠なく削除・復元しない。

## 完了状態

- 202606の動作基準と再現手順が確定している。
- 202607の状態が保全され、再始動ブランチと混同されていない。
- 202606 UIの正本が画面・操作・遷移単位で確認できる。
- 新JSライブラリの採用範囲が決まっている。
- 202607設計の移植は、機能単位の検証結果付きで進められる。
