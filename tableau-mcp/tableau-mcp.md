# Tableau MCP 個人環境PoC 予算取得用メモ

## 1. 背景・目的

Tableau 上の公開データソースやビューに対して、自然言語での探索・分析が可能かを、個人環境の PoC として短期間で確認することを目的とする。  
本メモは、対外説明用ではなく、社内での予算取得および実施可否判断のための整理資料である。

本検証では、Tableau MCP を利用し、MCP Client から Tableau 環境へ接続し、自社 LLM を介して自然言語で問い合わせる構成を想定する。

あわせて、以下を確認対象とする。

- 個人環境での最小構成において実現可能か
- 必要な Tableau 権限・認証方式が何か
- セキュリティ上の懸念がどこにあるか
- 小規模 PoC に必要な工数・費用感がどの程度か
- 今後、本番利用を見据える場合の論点が何か

## 2. 要約

本件は、外部向け提案ではなく、社内で Tableau MCP を用いた PoC を進めるための予算取得用整理である。  
そのため、構成の妥当性、必要権限、セキュリティ懸念、実施範囲、概算費用を中心に記載する。

### やりたいこと

- Tableau MCP を利用し、Tableau の公開データソースに対して自然言語で問い合わせ可能な構成を検証したい
- 自社 LLM と接続し、MCP Client から Tableau 情報を取得・分析できるかを確認したい
- 個人環境で MVP として成立するかを短期間で確認したい

### 確認したい事項

- 個人環境での Tableau MCP PoC 構成の妥当性
- Tableau 側の必要権限および認証方式
- 自社 LLM 利用時の接続前提および注意点
- 今回の PoC における実施範囲の妥当性
- 予算取得に必要な論点整理が十分か

### セキュリティに関する確認事項

- ローカル端末上での設定ファイル・トークン保管方法

- ログ・一時ファイルの取り扱い

### 実施内容

- 必要権限・認証方式・セキュリティ論点の整理

### 契約関連

## 3. Tableau MCP について

Tableau MCP は、MCP Client から Tableau 環境へ接続するための橋渡しを行う MCP Server である。  
自然言語の解釈そのものは LLM 側が担い、Tableau MCP は Tableau の公開コンテンツや公開データソースに対して必要な情報取得を行う。

今回の想定役割は以下の通り。

- MCP Client からの要求を受ける
- Tableau の公開データソースやビュー情報を取得する
- 必要なメタデータやデータ取得結果を LLM 利用フローに渡す

本 PoC においては、Tableau Desktop の直接操作や、未公開データソースの分析を主目的とはしない。  
あくまで Tableau 上で公開済みの対象に対して、自然言語による参照・探索が成立するかを確認する位置づけとする。

## 4. 想定構成

### 実施方針

MVP として、まずは個人環境で実施する。  
対象は単一ユーザー利用を前提とし、本番運用や複数人同時利用は対象外とする。

### 構成要素

- **MCP Server**  
  Tableau MCP をローカル端末上で実行する

- **MCP Client**  
  MCP Server を呼び出すクライアントを利用する

- **LLM**  
  自社 LLM を利用する

- **実行環境**  
  Windows 11 / VSCode を前提とする

- **利用候補ツール**  
  可能であれば Claude Code の利用可否も検討する

### 接続イメージ

1. 利用者が MCP Client 上で自然言語の問い合わせを実行する
2. MCP Client が Tableau MCP に対して必要なツール呼び出しを行う
3. Tableau MCP が Tableau 環境へ接続し、対象データソースまたはビュー情報を取得する
4. 取得結果をもとに、自社 LLM が自然言語応答を生成する

### 補足

- 個人環境での実施のため、サーバー共用やマルチユーザー制御は考慮しない
- PC スペック面では、MCP Server 自体よりも LLM 実行方式の影響が大きい
- 自社 LLM がクラウド型かローカル型かで、端末負荷やセキュリティ上の論点が変わる

## 5. 前提条件

本 PoC は以下を前提とする。

- Tableau 環境に接続可能であること
- 対象とする Tableau サイト、プロジェクト、公開データソースまたはビューが特定されていること
- 必要な Tableau 権限が付与可能であること
- 自社 LLM の接続先および利用条件が確認済みであること
- 検証用端末として Windows 11 / VSCode を利用可能であること
- 社内ネットワークから Tableau および自社 LLM 接続先へ疎通可能であること
- 必要に応じて Node.js 等の実行環境をローカル端末に導入可能であること

## 6. スコープ / 非スコープ

### スコープ

- 個人環境での Tableau MCP PoC 実施
- MCP Server と MCP Client の接続確認
- 自社 LLM と Tableau MCP の接続可否確認
- Tableau 公開データソースへの自然言語問い合わせ確認
- 最低限のログ・設定ファイル・認証情報の管理方針整理
- セキュリティ懸念点の洗い出し

### 非スコープ

- 複数ユーザー利用
- 本番環境導入
- 組織全体を対象とした認証統合
- 高可用性設計、負荷分散設計
- Tableau 権限体系全体の再設計
- 大規模性能試験
- 正式な運用手順書・保守手順書の整備
- 本番監視設計、障害対応設計

## 7. 権限・認証

### Tableau 側権限

最低限、以下の権限確認が必要となる。

- 対象データソースまたはビューに対する参照権限
- API Access の可否
- 必要に応じたメタデータ参照権限

### 認証方式

PoC においては、実装容易性を踏まえ、以下のいずれかを候補とする。

- Personal Access Token（PAT）
- Connected App
- OAuth

個人環境の短期 PoC では PAT が扱いやすい一方で、本番向きではないため、将来展開時には別途見直しが必要となる。

### 認証情報の保管

- ローカル端末上の設定ファイルへの保存有無を明確化する
- 平文保存を避けられるか検討する
- 保存場所を限定する
- 不要時に削除可能な運用とする

## 8. セキュリティに関する取り組み

本 PoC では、以下の観点でセキュリティ対応を整理する。

### 送信データ制御

- LLM へ送信されるデータ範囲を明確化する
- 必要最小限の情報のみ送る方針とする
- 機微情報を含むデータソースを対象にしない、またはマスキング要否を整理する

### 認証情報管理

- PAT や接続情報の保管方法を限定する
- 設定ファイルへの埋め込み有無を確認する
- 検証終了後に削除する

### ローカル端末管理

- 検証端末を限定する
- 不要な共有フォルダへの保存を避ける
- 一時ファイルやキャッシュが残る箇所を確認する

### ログ管理

- 何をログとして残すかを整理する
- ログに認証情報や機微データを含めない
- ログ保管場所と削除対象を明確にする

### 削除方針

検証終了後、以下を削除対象とする。

- MCP Server 関連設定ファイル
- 認証トークン
- ローカル保存ログ
- 一時ファイル
- 検証用に作成した補助スクリプトや接続設定

## 9. リスク・懸念点

- 個人環境 PoC のため、組織的な運用統制は限定的である
- 認証情報のローカル保持方法によっては情報漏えいリスクがある
- LLM への入力内容次第で、不要な情報送信が発生する可能性がある
- 自然言語解釈誤りにより、分析結果の粒度や条件が期待とずれる可能性がある
- 対象が公開データソース前提のため、利用可能範囲が限定される
- 本番導入時には認証方式・権限制御・監査ログの再整理が必要となる
- Claude Code 利用時は、社内ルール上の利用可否や外部送信範囲の確認が別途必要となる
