# Task 027: 202606再始動と202607設計の選択的移植

## 状態

未着手

## 目的

202606を動作原本として再始動し、202607の実装状態は保全したまま、必要なバックエンド設計だけを段階的に移植する。UIは202606の見た目・操作感・画面遷移を正本とする。

## タスク分解

### R-00: 202607状態の保全

- 現在のブランチ、HEAD、作業ツリー、未追跡ファイルを記録する。
- 202607改修状態をGitHub上で参照できるブランチまたはタグとして残す。
- 不明な変更を削除・上書きしない。

完了条件: 202607の現状へ戻れること、保全対象が明記されていること。

### R-01: 202606正常基準の特定

- 202606のブランチ、コミット、または最後に正常動作した地点を特定する。
- 起動、保存、読込、実行、主要画面の確認手順を記録する。
- 202606時点の既知の制約と不具合を分離する。

完了条件: 202606を再現できる基準と確認手順が決まっていること。

### R-02: 再始動ブランチ作成

- 202606の正常基準から `codex/rebaseline-202606` を作成する。
- 202607由来の変更を自動的に混ぜない。
- ブランチ作成直後の状態を記録する。

完了条件: 202606ベースの作業開始点が固定されていること。

### R-03: 202606システム動作確認

- `zizai.py` の起動経路を確認する。
- `.zizd` の保存・読込、workflow実行、主要connectorを確認する。
- 失敗した項目は修正せず、原因と扱いを記録する。

完了条件: 202606の動作範囲と残存不具合が一覧化されていること。

### R-04: 202606 UI正本の固定

- 画面ごとの見た目、レイアウト、操作、画面遷移を確認する。
- UI正本とする画面キャプチャまたは確認手順を保存する。
- 202607 UIとの差分は修正対象ではなく、移行判断材料として記録する。

完了条件: UIの受入基準を実装前に確認できること。

### R-05: JSライブラリ適合性調査

- 直近で追加されたJSライブラリを一覧化する。
- 202606 UI契約にそのまま再利用できるもの、adapterが必要なもの、採用しないものに分類する。
- document、state、bridge、designerの各責務混在を確認する。

完了条件: ライブラリ採用判断と接続順が決まっていること。

### R-06: 202606 UIへの段階接続

- AppShell、workspace、workflow画面、property/result、standalone等を画面単位で接続する。
- 各画面で202606の見た目・操作・遷移を維持する。
- UI変更ごとにブラウザ確認とfocused Playwrightを実行する。

完了条件: 202606 UIの主要導線が、新ライブラリを活用しながら復元されていること。

### R-07: 202607バックエンド設計の選択的移植

- document、catalog、runtime、security、resource、log等を独立した小タスクに分ける。
- 各移植前に202606の既存挙動と影響範囲を確認する。
- 移植単位ごとにunit／integration／必要なE2Eを追加・実行する。
- 202607のUI実装や不安定な結合状態は移植対象に含めない。

完了条件: 各設計移植が、既存動作を壊していない根拠付きで管理されていること。

### R-08: 再始動版の回帰確認と正本更新

- UI、backend、connector、起動、保存、実行の回帰確認を行う。
- `.docs/` と `.codex-harness/tasks/` の正本・状態を更新する。
- 202607保全状態、202606動作原本、移植済み設計の境界を明記する。

完了条件: 再始動版の現在地と次の作業が、202607の旧作業記録と混同せず追跡できること。

R-00 → R-01 → R-02 → R-03 → R-04 → R-05 → R-06 → R-07 → R-08
